## Identity, access, and common dependencies

The final packet must bind exact architecture blobs, packet/config blobs, final code/dependency/environment identity, evidence schemas, final checkpoint schema, generator/provenance validator, final case identities, final N-B1 seed/RNG identity, result-landing audit, and the parent prefreeze manifest.

Historical v0.1 evidence remains P0-D development evidence. Final confirmatory identities must be sealed before scientific result access. The access ledger must show whether any scientific values were opened and whether a later design/code change occurred. Any affected confirmation identity is retired rather than silently reused.

Cross-lane disjointness is proven over scientific ancestry, not labels alone. Source case, generator instance, template, seed/deterministic identity, parameter draw, transform ancestry, and derived/matched variants must be checked. Shared software is permitted only as a registered common dependency.

Every required common truth/reference dependency must have an independent verification route. Shared production code cannot validate itself. Required unresolved common dependencies block packet APQ.

## N-B2/N-B3

Confirm prospectively that:

- the final finite suite is exhaustively enumerated;
- every representation-equivalence class has a computable membership test;
- every matched contrast names held-fixed information, target, Function/Limit role, and expected mathematical relation;
- numerical tolerances verify calculations and do not define scientific equivalence after outcomes;

- the global/adaptive peak algorithm examines all candidate maxima and has an independent reference check;
- at least one continuous-time aliasing control contains multiple models compatible with the same sampled information unless extra information resolves them;
- partial-observation and misspecification cases are instantiated;
- learned DMD/Koopman remains outside v0.2 claim scope unless separately qualified;
- conclusions remain suite/target/observation-contract specific.

## Generator, provenance, and reference validation

Before scientific target evaluation, an outcome-blind validator verifies truth labels, held-fixed identities, same-spectrum relations, A/B/C/G/x0 relations, similarity transforms, switching sequence/phase, sampling projections, lane ancestry/disjointness, and packet/config/code/environment hashes.

Critical truth/reference premises use an independent analytic or separately implemented check as required by the common-dependency register. Failure is a contract refusal or NEED_MORE_INFO according to stage and cannot be repaired from scientific outcomes.

## Checkpoint and authority boundary

Final checkpoint identity includes parent manifest, lane, queue/order identity, completed-work cursor, case-set digest, packet/config/code/dependency/environment identity, RNG/seed identity when applicable, output-schema identity, artifact hashes, and run identity. Every mismatch refuses resume.

GitHub may validate identities, execute frozen cases, checkpoint/resume, hash/merge, and package evidence only. It cannot assign scientific sufficiency, qualification, rank, combined lane verdict, thresholds, prevalence, or claim promotion. Terminal automation state is SCIENTIFIC_REVIEW_READY.

## Closure

Every BLOCKER/MATERIAL objection is adjudicated individually. Any material change reopens the necessary APQ scope. Final execution authority remains false until architecture review, exact packet APQ, final scientific freeze, prospective v0.2 implementation, implementation tests, common-dependency verification, final identity binding, and lane-specific checkpoint validation have all closed.

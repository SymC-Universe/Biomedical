## Purpose

This authority closes the cross-lane objections identified by the independent v0.5 integration re-review. It does not merge the scientific questions or verdicts of the two lanes.

## Common-dependency control

All dependencies capable of affecting truth labels, reference targets, numerical rules, or both lanes must be listed in `V0_2_COMMON_DEPENDENCY_REGISTER_v0.1.json`.

Before exact packet APQ, each required truth premise must have an independent verification route. Acceptable routes are an analytic certificate, a separately implemented reference calculation, or another prospectively declared independent check appropriate to the object. A shared production implementation cannot validate itself.

A required unresolved common dependency blocks packet APQ. It cannot be repaired from scientific outcomes.

## Access and exposure lineage

`V0_2_OUTCOME_ACCESS_LEDGER_v0.1.json` is the access source of record. Final confirmatory identities must be designated and sealed before scientific result access.

Historical v0.1 evidence remains P0-D exposed development evidence. The new program is described as prospective post-exposure qualification. It may be described as value-uninspected only to the extent supported by the access ledger.

If a sealed confirmatory result is opened and a later scientific design or code change affects that case, the affected case is retired from confirmation and replaced prospectively. No adaptive reuse procedure is authorized by default.

## Cross-lane scientific ancestry

Final case separation follows `V0_2_CROSS_LANE_PROVENANCE_DISJOINTNESS_CONTRACT_v0.1.md`. Disjoint labels are insufficient. Source case, generator instance, template, seed or deterministic identity, parameter draw, transform ancestry, and derived/matched variants must be checked.

Shared software or mathematical infrastructure is allowed only as an explicitly registered common dependency with independent verification.

## Separate scientific authority

N-B1 qualification and N-B2/N-B3 representation sufficiency remain separate scientific verdict namespaces. Neither result can license the other. No combined PASS, universal representation rank, biological prevalence claim, real-EEG local chi, or whole-system scalar is produced by the integration layer.

`SCIENTIFIC_REVIEW_READY` is an execution/integrity terminal state only. Scientific adjudication is separate for each lane. Claim promotion requires separate researcher sign-off and ChatGPT scientific adjudication under the active GOM.

## Resume identity

Final lane checkpoints must bind the parent identity manifest, queue/order identity, completed-work cursor, case-set digest, code/dependency/environment identity, RNG/seed identity where applicable, artifact hashes, and run identity. Any mismatch refuses resume.

## Closure

This integration authority must receive isolated independent re-review. Architecture closure occurs only when N-B1 v0.5, N-B2/N-B3 v0.5, and this integration authority have no unresolved BLOCKER/MATERIAL objections.

Only after architecture closure may exact v0.2 packet construction and packet-level APQ begin. This document grants no execution authority.

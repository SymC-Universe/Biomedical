## Changed premise

Plan v0.2 required current A0/A1/A2 refitting on sentinel cells 0, 5, 10, and 15. Plan v0.3 removes those new refits from the active Function Map while retaining prior A0/A1/A2 qualification results as historical comparator evidence.

## Attack 1: does removal invalidate the scientific question?

No. The frozen Function Map asks where C1Q recovers the correct C-family coordinates and whether failures appear C1Q-specific or information-limited. The generic covariance-recurrence pole diagnostic remains the active independent-parameterization comparator for that attribution question.

The plan no longer makes a new claim that C1Q outperforms A0/A1/A2 across the qualification envelope. Therefore new A0/A1/A2 refits are not logically required to answer the current claim.

**Disposition:** \`REJECTED_WITH_EVIDENCE\` as a blocker to removal.

## Attack 2: does removal hide unfavorable prior comparator evidence?

No. Earlier qualification results remain in the working record and postresult set, including A1 false-selection pressure on nonzero-g truths, C1Q correction of some one-mode false A2 selections, C1Q absorption of colored-process truth, and genuine two-mode A2 controls. Plan v0.3 does not overwrite or recalculate those findings.

**Disposition:** \`DEFERRED_CLAIM_LIMITED\`. Any future comparative-performance claim against A0/A1/A2 must use or prospectively update that evidence in its own plan.

## Attack 3: could runtime itself be a scientific outcome?

No. The observed bottleneck occurred in the broad multi-start A0/A1/A2 optimizer on a local execution environment and is best classified as computational cost. It does not speak to truth-family validity or C1Q recovery.

**Disposition:** \`NOT_APPLICABLE\` to scientific interpretation; retained as a plan-execution failure.

## Attack 4: does removing the comparator create circular same-family validation?

The generic recurrence diagnostic remains deliberately distinct from C1Q's likelihood and nuisance parameterization. It shares the second-order truth assumption, so it cannot validate that biology belongs to C, but it can distinguish some information-limited regions from C1Q-specific failures. The claim ceiling remains correct-specification estimator Function Mapping.

**Disposition:** \`REJECTED_WITH_EVIDENCE\` as a blocker.

## Attack 5: is there a cheaper repair than plan change?

Reducing A2 starts or iterations would change the legacy comparator implementation and could alter its result. Running the unchanged comparator serially would make a nonessential descriptive control dominate the preflight and full-map resource cost. Separating it into another expensive branch would add work without answering the present Function Map question.

Removing the new refit while preserving prior comparator evidence is the least scientifically invasive repair.

**Disposition:** \`ACCEPTED_MODIFIED\`.

## Shared-premise challenge

The revised plan still assumes a true one-mode C family because that is precisely the Function Map object. Nothing in the revision makes that assumption more biologically plausible. The map remains unable to establish biological prevalence or family membership in real data.

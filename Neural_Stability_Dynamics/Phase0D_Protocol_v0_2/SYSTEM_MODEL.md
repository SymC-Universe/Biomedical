# Neural Stability Dynamics System Model v1.0

Date locked: 2026-09-11
Governing protocol: **General Cross-Project Research Protocol v0.7.1 FINAL + authoritative v0.7.1A Addendum**
Lock status: **ARCHITECTURE_FROZEN_P0. ESTIMATION / QUALIFICATION RULES REMAIN VERSIONED AND UNFROZEN WHERE LISTED.**

## 1. Purpose and claim ceiling

The NSD System Model is a formal representation for asking **what dynamical organization is identifiable in multichannel neural time series, at what level of resolution, under what model adequacy, and with what uncertainty**.

The model does **not** assert that neural dynamics are universally linear, second-order, critically damped, generated by one mechanism, clinically diagnostic, causal, or predictive. It does not require every dataset to admit a coherent scalar coordinate. Refusal, partial resolution, indeterminacy and model inadequacy are valid model outputs.

The System Model is distinct from:

- the **NSD Structural Engine**, which is an implementation used to estimate System-Model objects;
- the **Neurostability Atlas**, which is an independent evidence/coordinate resource;
- the future **NSD Tool**, which requires a qualified Engine plus qualified Atlas;
- any future predictive tool, which additionally requires prospective empirical validation.

## 2. Native local representation

Within a time window where a stochastic state-space representation is adequate, the working local representation may be written generically as

`x_(t+1) = A x_t + w_t`

`y_t = C x_t + v_t`

or by an equivalent continuous-time generator after a justified transformation.

This is an **identification representation**, not automatically a literal neural mechanism. The observable time series `y_t`, not an inaccessible latent state basis, is the empirical starting point.

If model adequacy is not supported at the requested level, the corresponding structural claim is limited, refused or left unresolved rather than forcing the representation.

## 3. Frozen System-Model object hierarchy

The fullest NSD description is explicitly **not one scalar**. It is the joint, non-arithmetic description of:

`scalar / spectral structure + modal / carrier structure + conglomerate / system organization + open-channel state`

These views are complementary. None is permitted to silently replace the others.

### 3.1 Scalar / spectral object

For an identified local generator, the native spectral objects are its supported poles/eigenvalues.

For a continuous-time pole

`lambda_j = sigma_j + i omega_j`,

native mode-resolved coordinates may include, where defined:

- real part / decay coordinate `sigma_j`;
- angular-frequency coordinate `omega_j`;
- frequency `f_j = omega_j / (2*pi)`;
- stable/unstable/non-oscillatory classification;
- decay time or another algebraically equivalent quantity when the transformation is explicit;
- pole uncertainty and persistence when qualified.

A **whole-system scalar is not part of the frozen System Model** unless separately derived and validated.

`chi` is **WITHHELD by default**. A mode-level or system-level chi coordinate may enter only when the native model supports the required second-order factorization/parameter interpretation and the transformation is explicitly derived, versioned and validated. The Atlas and Engine may not manufacture chi from a generic complex pole merely because a numerical ratio can be formed.

### 3.2 Modal / carrier object

The modal object describes how supported dynamical structure appears in the observable channels.

Frozen distinctions:

- an **individual carrier/mode** is a claim object only when one-to-one identity is sufficiently identifiable;
- a **crowded carrier subspace** is a distinct claim object when individual labels are not stable but the joint invariant/observable subspace remains identifiable;
- individual-mode identity and subspace identity are never treated as equivalent claims;
- carrier/channel structure is observational and basis-aware; it is not automatically anatomical mechanism.

P0-D3 establishes why this distinction is required: decreasing modal separation can substantially degrade individual carrier matching while leaving the joint carrier subspace strongly recoverable.

### 3.3 Conglomerate / system-organization object

The conglomerate view describes how supported mode-resolved structure is organized as an observable system.

Frozen System-Model objects include, where resolvable:

- **local observable order/rank**;
- **whole supported observable subspace**;
- **channel participation / leverage distribution**;
- **crowding/cluster structure**;
- **relational spectral geometry** between resolvable mode or cluster objects;
- **added, lost, shared or reorganized structure** across windows/conditions;
- system-level `ADMIT`, `PARTIAL`, `REFUSE`, `UNRESOLVED` or `INDETERMINATE` status assembled without hiding layer-specific results.

The conglomerate view is not the arithmetic sum of modal coordinates and is not replaced by a single chi value.

### 3.4 Open-channel object

The open channel is a first-class System-Model component, not discarded error output.

It contains, as applicable:

- local observable-order changes;
- unmatched / added / lost modes or subspaces;
- estimator disagreement;
- model-adequacy diagnostics;
- residual/model-error structure;
- out-of-sample reconstruction/prediction behavior;
- uncertainty and assignment ambiguity;
- failed or unstable fits;
- rejected structures;
- unresolved carrier geometry;
- missing transformations;
- `NOT_APPLICABLE` objects;
- any observation that cannot be placed honestly into the other three views.

A future model extension may promote a repeated open-channel pattern into a new explicit System-Model object only through a versioned scientific revision. It may not be silently absorbed into v1.0.

## 4. Latent dimension is not observable dimension

This distinction is frozen.

`latent state dimension != observable structural dimension`

A latent generator may contain structure that is too weakly represented in `C` or in the measured channels to remain individually identifiable. P0-D2 demonstrated that an observable-rank estimate can decrease while the dominant observable structure remains accurately recoverable.

Therefore:

- failure to reconstruct the full planted/latent order is not automatically failure of observable structural recovery;
- local observable order is a scientific object in its own right;
- a change in observable order must remain visible rather than being forced into equal-order comparison.

## 5. Crowding and identifiability

Crowding is treated as an identifiability problem before it is treated as disappearance of structure.

For mode pairs/clusters, a dimensionless separation coordinate such as

`|omega_i - omega_j| / (alpha_i + alpha_j)`

may be used as a **method/native crowding descriptor** when all terms are defined, but no v1.0 universal crowding threshold is frozen.

When individual identities become unstable while the joint subspace remains stable:

- individual carrier claim: `UNRESOLVED` or otherwise limited;
- joint subspace claim: may remain supported;
- relational geometry must operate on resolvable objects/clusters, not arbitrary unstable labels.

## 6. Claim-specific gates and partial results

System-Model claims are layer-specific.

A failure in one layer may limit claims that logically depend on it but may not erase narrower supported observations in another layer.

Examples:

- modal carrier recovery may be supported while system relational geometry is unresolved;
- observable rank may be supported while latent completeness is not;
- a stable pole set may be present while model adequacy is insufficient for a stronger dynamical claim;
- a crowded invariant subspace may be supported while individual mode identity is indeterminate.

The System Model therefore prohibits a single aggregate score from converting contradictory layer evidence into one compensating pass.

## 7. Model adequacy is an epistemic requirement

A numerically stable fitted spectrum is not sufficient by itself.

The frozen adequacy architecture requires the following categories to remain separately visible where the claim depends on them:

- within-window residual/model-error temporal structure;
- out-of-sample reconstruction or prediction;
- fitted stability/admissibility;
- order/window sensitivity;
- method exceptions and unresolved diagnostics.

P0-D4 showed that these diagnostics can fail in complementary directions. Exact numerical thresholds, lag policies, confidence levels and final adjudication consequences remain **unfrozen P0-Q work**.

Generic output-prediction residuals must not be mislabeled as SSI innovations unless an actual SSI/Kalman innovation construction has been derived.

## 8. Uncertainty and indeterminacy

Uncertainty is part of the epistemic state of every claim for which it can change adjudication.

Frozen principles:

- uncertainty must correspond to the estimator/object actually computed;
- method/order/assignment/crowding ambiguity may require more than a scalar standard error;
- `INDETERMINATE` is a valid result when supported uncertainty spans incompatible claim states or identifiability is insufficient;
- uncertainty may not be imported from a numerically similar but finite-sample-incompatible estimator without justification.

The pyOMA2 external reference confirms a viable covariance-SSI uncertainty lineage but direct transfer to the current NSD finite-sample covariance estimator is not licensed. P0-D5 shows that an NSD-native batch covariance candidate captures the shape of Hankel sampling variance strongly but still has duration/batch-dependent scale bias. Modal propagation and final uncertainty rules remain **unfrozen**.

## 9. Function Map and Limit Map

Under General Protocol v0.7.1A, the System Model explicitly supports two coequal maps:

### Function Map

Where does a specific claim object remain identifiable/useful, at what resolution, under what perturbation, adequacy and uncertainty?

### Limit Map

Where does that claim object degrade, reorganize, become non-identifiable, require a different representation, or correctly refuse?

The location states are claim-specific:

- `WORKS_HERE`;
- `STOPS_WORKING_HERE`;
- `NOT_KNOWN_HERE`.

These P0 map states are descriptive and do not constitute P1 confirmation.

## 10. Coverage roles

Where applicable, System-Model evidence is tagged by research role:

- `NOMINAL_FUNCTION`;
- `PERTURBED_FUNCTION`;
- `BOUNDARY_OR_TRANSITION`;
- `RARE_NATURAL_LIMIT`.

The role describes the evidence context and does not determine the result in advance. `NOT_APPLICABLE`, `NOT_AVAILABLE` and `UNRESOLVED` remain legitimate.

## 11. Neurostability Atlas relationship

The Neurostability Atlas is **external to the Structural Engine** and read-only with respect to Engine rule construction during confirmatory use.

The Atlas may organize native and explicitly licensed derived coordinates corresponding to System-Model objects, including:

- spectral/pole coordinates;
- modal/carrier and subspace coordinates;
- observable-order and participation coordinates;
- crowding/relational-system coordinates;
- model-adequacy descriptors;
- uncertainty/identifiability descriptors;
- functional/perturbation/transition/rare-limit context.

Atlas content does not become an Engine selector input merely because the coordinate names correspond to Engine outputs.

All Atlas coordinates retain provenance, derivation status, units, context, evidence tier and pathway-specific independence.

## 12. Structural inference firewall

The following may not enter Structural-Engine selector decisions unless a future separately justified scientific design explicitly changes the claim class:

- truth used only for synthetic scoring;
- chi used as a desired answer;
- diagnosis;
- phenotype;
- treatment;
- treatment response;
- clinical outcome;
- labels;
- desired historical ordering;
- Atlas target values used to force agreement.

The structural model must be estimated from permitted signal/model objects first. Biological or clinical interpretation is downstream.

## 13. Frozen epistemic states

The System Model recognizes at least:

- `ADMIT` / supported at the stated claim level;
- `PARTIAL` / some required subclaims supported while others remain unresolved;
- `REFUSE` / required support absent or contradictory for the stated claim;
- `UNRESOLVED` / evidence or representation cannot distinguish the requested object;
- `INDETERMINATE` / uncertainty or admissible alternatives span incompatible states;
- `NOT_APPLICABLE` / the object is not meaningful in that context.

Exact implementation strings may vary by layer/version, but their epistemic distinction is frozen.

## 14. Scope

Scope is earned and attached to the specific supported object. Preferred scope classes include:

- `SUPPORTED_IN_TESTED_REGIME`;
- `CROSS_REGIME`;
- `CROSS_SYSTEM`;
- `ROBUST_ACROSS_TESTED_LIMITS`;
- `REGIME_LIMITED`;
- `DOMAIN_LIMITED`;
- `UNRESOLVED_BEYOND_TESTED_RANGE`.

`UNIVERSAL` is not a target designation for NSD v1.0.

## 15. What this lock freezes

System Model v1.0 freezes:

1. the four-view architecture: scalar/spectral + modal/carrier + conglomerate/system + open channel;
2. the distinction between latent dimension and observable dimension;
3. the distinction between individual carrier identity and crowded-subspace identity;
4. claim-specific gating and preservation of partial/unresolved results;
5. model adequacy as an epistemic requirement separate from structural recovery;
6. estimator-native uncertainty/indeterminacy as a requirement for claims that depend on it;
7. Function Map + Limit Map as coequal scientific targets;
8. the structural inference firewall;
9. Atlas independence from Engine rule construction;
10. withholding whole-system chi and any unlicensed mode-level chi transformation;
11. bounded scope and non-universality;
12. open-channel preservation rather than silent discard.

## 16. What this lock does NOT freeze

The following remain versioned implementation/qualification work and do **not** require changing System Model v1.0 unless they change the object ontology above:

- SSI-COV implementation details;
- Subspace-DMD or any comparator implementation;
- operational rank/order selection rules;
- numerical singular-gap thresholds;
- crowding thresholds;
- MAC/subspace/participation/geometry thresholds;
- model-adequacy numerical thresholds or lag/window policy;
- uncertainty propagation method, confidence convention and multiplicity rule;
- P1 challenge matrix, seeds, scoring or adjudication;
- Atlas coordinate values and empirical population ranges;
- clinical/phenotypic interpretation;
- any future second-order/chi derivation.

Changes to those items may produce Engine/Atlas versions without reopening the System Model architecture. A change to the frozen object hierarchy or logical relationships requires an explicit System Model version increment.

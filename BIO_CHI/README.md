## Reproducibility rule

Anything required for a reviewer to understand, rerun, audit, or falsify a promoted result should be committed here when legally and technically possible:

- source identifiers and hashes;
- acquisition instructions;
- preregistrations and amendments;
- executable code and pinned environments;
- tests and known-bad cases;
- compact result tables;
- figure/table generation code;
- null/failure/refusal ledgers;
- claim-to-evidence maps;
- exact workflow run and artifact identities;
- checkpoints and execution state.

Large third-party raw data are not copied into Git when redistribution is inappropriate. Their exact source identity, hash, retrieval path, and transformation route are recorded instead.
